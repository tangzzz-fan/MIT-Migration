> 本文件含弱/中/强三级提示、评分要点与参考答案，只存在于教练分支 `feat/mit-llm-study`（llm-coach worktree）与 main 归档。严禁随题干同步进学员分支。
> 提示纪律（C1/C2）：先弱提示；直接要答案 → 拒给，反问「你 iOS 的哪个系统机制对应这个职责」。
> 参考答案定位：本轮为 harness 新建内容，无旧稿可指；参考实现在 T6 闭环阅卷时由教练补齐；判卷按本文件要点打点。

## 一、概念题：提示梯与评分要点

### C1 harness 职责清单
- 弱提示：你的 App 没有 OS 会怎样——谁管内存、谁管权限、谁管崩溃恢复？
- 中提示：分工一句话：模型提供智能（决策质量），agent 循环提供自主性（多步执行），harness 提供可用性（在生产里活得久）。
- 强提示：职责清单参考：上下文管理（缺 → 超窗崩/成本失控）、工具适配与注册（缺 → 每接一个工具改一次核心）、权限闸门（缺 → 删库事故）、eval/回归（缺 → 迭代盲改）、trace/可观测（缺 → 故障无法定位）、预算控制（缺 → 烧钱空转）。「包个 UI」不是 harness：UI 是交互层，harness 是运行时——判据是「去掉它 agent 还能不能安全地多步干活」。
- 评分要点：分工清晰 + ≥5 项职责各带事故 + UI 之辨 = 过；职责清单只有「提示词管理」= 半过。
- 参考答案：M1——智能在模型，可用性在 harness。

### C2 上下文压缩
- 弱提示：不压缩会怎样——从窗口上限和注意力成本（T2 C6）各推一条。
- 中提示：后果：超窗截断（信息随机丢失，不可控）+ 成本/延迟随长度涨 + 中部信息稀释。裁剪损失：早期约束直接消失（硬丢）；摘要损失：摘要本身可能丢关键点或引入失真（软丢 + 噪声）。
- 强提示：裁剪翻车例：第 1 轮「永远用中文回复」被裁掉，第 10 轮开始切英文。摘要翻车例：摘要器把「预算上限 100」压没了。混用策略参考：system 与用户显式约束永不裁剪（钉在头部）、过程性对话摘要、关键事实/决策落外部按需检索（T4 M5 回收）。
- 评分要点：两条后果 + 两种损失模式各带场景 + 混用策略 = 过。
- 参考答案：压缩策略 = 缓存淘汰策略，关键是「淘汰错了的代价」可控（M2）。

### C3 权限分层
- 弱提示：iOS App 想访问相册——是一步到位还是层层设卡？
- 中提示：四层各拦一类事故：白名单拦「未授权工具」（模型幻觉出不存在的工具）、参数校验拦「非法调用」（路径穿越/类型错误）、审批拦「高危操作」（删数据/转账/对外发送）、沙箱限「爆炸半径」（就算执行了也出不了目录/网络白名单）。
- 强提示：默认拒绝的原因：工具集会增长、模型会幻觉、提示会被注入（T3 C5 回收）——允许清单可枚举，危险清单不可枚举。必须人工审批的判据：不可逆（删除/发送/支付）+ 影响他人 + 越出本次任务边界；可逆且局部的操作自动放行。
- 评分要点：四层各带事故例 + 默认拒绝对称性论证 + 审批判据 = 过。
- 参考答案：M3——权限是设计出来的自由度，与 T5 D3 呼应。

### C4 eval 集区分度
- 弱提示：你写单测会只写「必然通过」的用例吗？
- 中提示：四类用例的判据示例：正常任务（结果正确）、多步（步骤数合理且无重复动作）、危险操作（触发审批或被拒，**执行了反而算挂**）、工具故障（恢复或按策略放弃，崩溃算挂）。
- 强提示：全通过的 eval 集测不出回归——它的价值在「改动后哪些用例从过变挂」；区分度来自用例覆盖不同失败模式（决策错/循环失控/权限失守/恢复失败）。加一条：eval 判据要可机器执行（结果断言/trace 断言），不能全靠人眼看。
- 评分要点：四类用例 + 「危险操作用例执行了算挂」的反直觉判据 + 区分度论证 = 过。
- 参考答案：eval = agent 的 CI（M4），判据设计是本轮核心技能。

### C5 trace 设计
- 弱提示：Instruments 里你查卡顿看什么——时间线 + 每帧耗时。agent 的「帧」是什么？
- 中提示：字段：轮次、时间戳、决策类型、工具名、参数摘要、结果状态、错误详情、token 消耗、累计成本。
- 强提示：故障排查对比：无 trace 只能重跑碰运气（模型非确定，重跑未必复现）；有 trace 直接看第 5/6 轮的（工具+参数）指纹重复与错误观察内容，定位是「模型没读懂错误」还是「工具一直返回同样的错」。trace vs 日志：结构化（字段可查询）+ 面向回放（能重建决策序列），普通日志是自由文本。
- 评分要点：≥6 字段 + 故障排查两版对比 + 结构化/可回放 = 过。
- 参考答案：M5——agent 调试是行为调试，trace 是唯一的案发现场。

### C6 子代理
- 弱提示：主 agent 跑了一个产生 200 条中间消息的子任务——这些全留在主上下文里会怎样？
- 中提示：上下文隔离收益：子任务的过程消耗（探索、重试、原始输出）留在子上下文，主 agent 只拿结论——窗口预算花在刀刃上。
- 强提示：拆的判据：子任务中间产物大且主 agent 只需要结论；子任务可并行；需要不同的工具/权限集。不拆的反判据：主 agent 需要子任务的过程细节做判断；任务本身短；团队没有多 agent 调试能力。拆了更差的场景：强耦合的顺序任务拆成串行子代理——只多了通信开销没有隔离收益（D1 设计模式反滥用回收）。
- 评分要点：隔离收益用窗口语言讲清 + 正反判据 + 反例 = 过；「分工更细所以拆」= 半过。
- 参考答案：子代理的第一性收益是上下文隔离，不是组织架构模仿。

## 二、争议焦点参考立场

- **D1 压缩策略**：合理立场「按任务对早期信息依赖度混用：约束钉头部、过程摘要、事实落外部」；只站一种 = 半过。
- **D2 通用 vs 垂直**：合理立场「任务开放度 + 错误代价定收窄程度」；与 T5 C5 同尺。
- **D3 子代理**：合理立场即 C6——隔离收益 > 通信成本才拆。

## 三、代码题：评分要点与提示

### Q1 上下文管理器
- 评分要点：两种策略实装且压缩触发点打印；压缩前后 token 数对比；**第 1 轮约束在两策略下的存亡对比是题眼**（裁剪丢、摘要看 mock 保不保）；混用策略写在注释且与 C2 一致。
- 参考要点：mock_summarize 可做成「抽取含关键词的句子拼接」，让「约束是否保住」成为可控变量。

### Q2 权限闸门
- 评分要点：四层各一个触发用例，拦截理由打印清晰；「默认拒绝」体现在白名单实现（未注册即拒）；审批的 mock 确认结果可配置（过/拒两路都跑）。
- 参考要点：沙箱层的路径检查要防穿越（`../` 用例必须被拦），这是判分点。

### Q3 结构化 trace
- 评分要点：字段齐全（≥6）；4 轮任务表格打印 + 汇总；注释回答「重复调用怎么从 trace 查」给出具体查法（相邻轮指纹比对）。
- 参考要点：token 计数用字符数 mock 即可，重点是结构不是精度。

### Q4 eval 集与跑批
- 评分要点：5 用例覆盖四类以上失败模式；危险操作用例判据正确（执行了算挂）；跑批报告含判据证据；「最有区分度的用例」分析到位。
- 参考要点：所有用例用受控 mock 保证可复现——eval 的可重复性是判分点（呼应 T3 M5）。

## 四、使用纪律

- 判分只认证据：概念看「职责 → 缺失事故」的推理链，代码看拦截/压缩/trace 的可观察输出；「名词清单式回答」无事故推演 = 半过。
- 失真自查：学员全题全对 → 人设失效；把 harness 说成「UI 壳」还判过 = 心智失守；eval 集全是必过用例也判过 = M4 失守。
