# T7 Q4 架构复盘记账（参考解法模板，仅教练分支）

> 复盘格式：问题-约束-代价三行账；结论必须与账一致（账说值得但结论删了 = 半过）。

## 一、六组件三行账

### 1. LLM 适配器
- 问题：循环与具体模型耦合，换模型/mock 要改核心
- 约束：eval 必须可复现（受控 mock）、生产要换真 API
- 代价：多一层接口抽象；决策输出格式要约定死（dict 契约）

### 2. 工具注册表
- 问题：加工具改循环 → 回归风险 + 幻觉工具名无统一拦截点
- 约束：工具集会增长；schema 要能喂给模型当说明书
- 代价：注册样板代码；描述质量成为决策正确率上限（新负债点）

### 3. agent 循环
- 问题：单次调用做不了多步任务
- 约束：必须有双终止（最终答案 + 最大轮数），否则烧钱空转
- 代价：失败模式新增「决策错」一类（绕圈/提前收尾），测试从断言变行为分布

### 4. 上下文管理
- 问题：窗口是硬预算，长任务必超
- 约束：system/显式约束不能丢；压缩有信息损失
- 代价：摘要引入失真风险；策略选择本身要 eval 验证

### 5. 权限闸门
- 问题：模型会幻觉调用、提示可注入，危险操作不能裸奔
- 约束：默认拒绝；危险清单不可枚举 → 白名单制
- 代价：审批增加人工环节；过严会挡合法操作（误杀也是成本）

### 6. trace
- 问题：agent 的 bug 是行为级的，没 trace 只能靠猜
- 约束：非确定性 → 故障未必能重跑复现，留痕是唯一案发现场
- 代价：每轮记录开销与存储；字段设计不好等于没记

## 二、重来会删/简化的组件

- **候选：上下文管理的 summarize 策略**——本收束项目任务都在 6 轮内，窗口从未触顶，摘要路径一次没跑过。账算不平（复杂度 > 收益）→ 先只留 trim，等 T6 场景真出现再加回。删除理由：它当时解决的问题（长任务超窗）在这个 harness 里还不存在。

## 三、mock 换真 API 的改动清单

| 组件 | 是否要动 | 说明 |
|------|---------|------|
| LLM 适配器 | 换实现 | MockLLM → RealLLM（httpx/SDK），接口不变 |
| 工具注册表 | 不动 | 只依赖调用 dict 契约 |
| agent 循环 | 不动 | 只依赖 complete() 返回结构 |
| 上下文管理 | 微调 | token 计数从字符数换成真实 tokenizer |
| 权限闸门 | 不动 | 拦截的是调用结构，与模型无关 |
| trace | 微调 | 增加延迟/费用字段 |
| **eval 判据** | **重新校准** | 真模型路径更多样：路径断言放宽为结果断言（锁结果不锁路径） |

## 四、一句话结论：最脆弱的环节

**工具描述质量**——它是模型决策的说明书，描述含糊则选错工具/传错参数，而上层所有组件（校验/闸门/trace）都只能在错误发生后补救；且描述质量无法靠单测保证，只能靠 eval 回归盯。次脆弱：mock 与真模型的行为差（换真 API 那天 eval 会大面积重校准）。
