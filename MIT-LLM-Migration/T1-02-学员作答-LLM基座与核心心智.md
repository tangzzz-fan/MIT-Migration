## 一、概念题作答

### C1 什么是 token？为什么 LLM 不是「按字处理」文本？

**思考过程**：iOS 键盘联想词给我的直觉——联想的单位不是字符，是「词块」。LLM 大概类似：内部有个「处理单元」，文本先被切成这种单元。中文一个字大概就是一个单元，英文……不确定，可能是单词？

**结论**：token 是模型处理文本的最小单元，文本先被 tokenizer 切成 token 序列再进模型，所以模型不是逐字看的。中英 token 数差异——我猜中文一字一 token、英文一词一 token，所以英文更省。至于「strawberry 数不对 r」，我猜是因为模型不以字母为单位看，但具体机制说不清。

**自评**：【半懂半猜】。卡点：BPE 是什么机制、为什么中英费 token 方向我可能猜反了，完全没底。

### C2 你第二次问同一个问题，模型「内部」发生了什么？

**思考过程**：用 App 发布流程类比——「改代码」发生在开发编译期，「跑 App」发生在用户运行期，运行时不改二进制。模型「变聪明」应该发生在某个离线阶段（训练？），我调 API 时它只是「跑」。

**结论**：① 训练是提前做好的（像编译发布），推理时只是执行，不再改自己；② 不记得昨天的对话，大概因为每次请求是独立的（像 HTTP）；③ 「聊久了越来越懂我」——我觉得一半对一半错：对话中它确实表现得越来越懂，可能是它慢慢记住了我的习惯？但又和②矛盾……这里我想不圆。

**自评**：【半懂半猜】。卡点：「越来越懂我」的机制我说不圆——如果模型不学习，那「懂」从哪来？

### C3 为什么同一个 prompt 每次输出不一样？temperature 和 top-p 各管什么？

**思考过程**：Python 线概率存量挂靠：输出不一样，说明不是查表，是「从多个候选里选」，选择带随机性。temperature 字面像「热度」——越高越随机？top-p 完全没概念，p 是 probability？

**结论**：随机性产生于「模型对下一个词有多个候选，每次按某种随机方式挑一个」。temperature 越高输出越发散、越低越保守（我猜它调节的是候选的「门槛」）。top-p 我纯猜：挑累积概率到 p 的那批候选里选。工程判断：要稳定输出的（格式化数据）用低 temperature，要多样性（文案）用高的。

**自评**：【半懂半猜】（top-p 部分接近【纯猜】）。卡点：temperature 到底作用在什么量上，我讲不出机制。

### C4 上下文窗口是什么？「模型记得我」的真相是什么？

**思考过程**：这题我主场——HTTP 无状态服务：服务器不记得上一次请求，登录态靠每次把 token/cookie 全带上。LLM 应该同构。

**结论**：① 模型无状态，每次调用必须把全部历史拼进请求，「记得你」= 历史还在这一单的输入里；② 超窗 = 输入装不下了，会被截断，被截掉的部分对模型等于从未存在；③ 长对话又贵又慢，因为每轮都要全量携带历史，token 按量计费，越聊越贵。iOS 类比：窗口像一次请求的内存上限。断裂处：iOS 内存释放后数据还能从磁盘读回来，但上下文被截掉的信息对模型是永久消失——除非外面另有存储。

**自评**：【有把握】。

### C5 幻觉为什么不是 bug？工程师该怎么「为幻觉设计」？

**思考过程**：我用 LLM 产品时被胡说八道坑过，我的一贯理解是：训练数据里有错误内容，模型学坏了；或者模型「偷懒」不认真查。

**结论**：幻觉的原因我认为是训练数据噪声 + 模型有时会瞎编。对策：① 提示里写「你要严谨，不知道就说不知道」；② 关键信息人工复核。这题我心里不踏实——如果提示一句就能解决，为什么所有产品都还在犯？

**自评**：【半懂半猜】（其实偏心虚）。卡点：幻觉的机制成因我只有「数据不好」这一种解释。

### C6 「LLM 只是随机鹦鹉」——有边界的立场

**思考过程**：我平时用下来「感觉」模型是理解我在说什么的，不像复读机。

**结论**：我反对「只是随机鹦鹉」。它能把没见过的任务组合做对，能按我的要求改输出风格，这不像纯复读。至于什么条件下站哪边……我没想过判据，就是觉得它「真的懂一点」。

**自评**：【半懂半猜】。卡点：我的立场全靠感觉，给不出可观察的判据。

### 争议焦点 D1–D3 简短立场（附加）

- **D1 scaling vs 工程**：我站「工程优先」——iOS 经验里性能问题九成靠工程不靠换硬件。但我说不出 scaling law 是什么。
- **D2 推理模型默认开**：不该默认开，按任务难度来——和「不是所有页面都该上最重架构」一个直觉。
- **D3 幻觉可治**：我原来以为能治（提示写好点），现在做完 C5 有点动摇。

### Q2 mock 概率采样器 → `代码/T1/Q2-mock采样器.py`

自评【半懂半猜】。输出：

```
理论分布     : 好:0.450  行:0.250  可以:0.150  也许:0.100  不好说:0.050
greedy x1000  : ['好']
T=0.5      : 好:0.699  行:0.184  可以:0.075  也许:0.035  不好说:0.007
T=1.0      : 好:0.468  行:0.236  可以:0.146  也许:0.097  不好说:0.053
T=2.0      : 好:0.334  行:0.254  可以:0.172  也许:0.140  不好说:0.100
top_p=0.7    : 好:0.637  行:0.363  可以:0.000  也许:0.000  不好说:0.000
top_p=0.9    : 好:0.484  行:0.277  可以:0.141  也许:0.098  不好说:0.000
```

三条验证结论都有数据：greedy 恒定、T 越大低频候选越多（分布变平）、top_p=0.7 核外频率为 0。撞墙 2 处（见文件头）：墙 1 是逻辑墙——top-p 没先按概率降序排，核选错，频率表对不上理论才暴露；墙 2 是截断后没归一化，语义上核内应是完整分布。temperature 实现我用 `p**(1/T)` 再归一（Python 线 softmax 存量推的），但「为什么这样就等价于调温度」我只能讲到形状变化这一层。

### Q3 上下文窗口实验 → `代码/T1/Q3-上下文窗口实验.py`

自评【有把握】。关键输出：

```
[轮3] 抽查『我叫什么』: 你叫王小明，请记住我的名字。（我还能看到这条信息）
[轮5] 被丢弃 2 条，最早一条是: 我叫王小明，请记住我的名字。…
[轮6] 抽查『我叫什么』: 我不记得你叫什么了。（这条信息不在我这次的输入里）
```

遗忘精确发生在名字消息被挤出窗口的轮次（第 5 轮丢、第 6 轮抽查即失忆）——这把我 C4 的「截断即遗忘」从类比变成了可复现实验。撞墙 1 处：budget 统计口径一开始把回复也算进去，和 chat 行为对不上，修正为「下一次请求要带的历史」。

### Q4 幻觉最小复现 → `代码/T1/Q4-幻觉最小复现.py`

自评【有把握】。输出：

```
100 次采样：命中知识库 65（65%），编造 35（35%）
真实答案样例 : ('地球围绕什么转', '答案是：太阳。')
编造答案样例 : ('恐龙灭绝的确切原因是什么', '这是一个经典问题：……标准答案是「1972 年贝尔实验室的内部备忘录」。')
```

编造率只取决于知识覆盖率；编造答案的语气和真实答案一样笃定——**流畅与自信都不携带真值信息**。这直接冲击了我 C5 的回答：mock 根本没地方写「数据噪声」，幻觉照样出现。我特意没给 mock 加「不知道」分支：这个行为得被训练/提示出来，不是天生的。

## 四、复攻记录与销账（批改后补记，2026-08-19）

> 教练判定：概念 1过3半2未、代码 3过1半（见 T1-03）。提示级数如实记录：全部从弱提示起步，两级点醒、三级自推。

### C1 复攻（弱 → 中，中提示点醒）

弱提示（键盘联想单位）没点醒；中提示（tokenizer 是翻译层，「好」是一个单元、strawberry 可能是多个单元）点醒。自推销账：BPE 把语料里高频的子串合并成一个单元——"the"、"ing" 这种片段会成为单个 token，所以常见英文词 ≈1 token、长罕见词才拆段；中文在多数词表里一字一 token（合并机会少）。**我原来猜反了**：同一语义中文通常比英文费 token；我字符级实验里英文更费，是因为字符级切分根本不代表真实 tokenizer。「数不对 r」的机制：strawberry 可能整个就是一个单元，字母级信息在 tokenize 阶段被抹掉——模型从没看见过字母。

### C2 复攻（弱，直接点醒）

弱提示（App 分发流程）就点醒了：「越来越懂我」的「懂」不在权重里，在上下文里——产品把全部历史拼进每次请求，历史越长表现得越「懂」；模型本身零学习，换一个不带历史的新会话一切归零。与我 Q3 实验同构：名字消息在窗口里就答得出，被挤出去就失忆——「记忆」就是窗口内的历史，别无其他。

### C3 复攻（弱 → 中，中提示点醒）+ Q2 机制销账

弱提示（分布形状）没点醒；中提示（T 改分布形状、p 改候选集）点醒。销账：temperature 不是「调门槛」，是作用在分布形状上——等价于 logits 除以 T 再 softmax：T<1 分布变尖（更保守），T>1 变平（更发散）。我自己的数据就是证据：T 从 0.5→2.0，「不好说」频率从 0.007 涨到 0.100——低频候选被拍起来，就是分布变平。top-p 口述补齐：按概率降序累积到 p 截断，核内重归一化后采样——截断只是选候选，重归一化才让核成为新的完整分布（Q2 墙 2 的语义自觉在这里接上了概念）。greedy/T→0 是确定性特例：随机性内建于采样，确定性是关掉采样。

### C5 复攻（弱 → 中，中提示点醒，用上了我自己的 Q4 输出）

弱提示（目标里有没有「真」字）没点醒；中提示（bug = 实现偏离目标；如果目标本来就是流畅续写呢）点醒。销账：模型的目标是「产出最像训练数据续写的下一个 token」，里面没有真值校验环节——知识缺失时分布照样要给答案，于是编造得流畅又自信。**这不是 bug，是目标的忠实执行**；「数据噪声」归因作废。我的 Q4 mock 就是最小证明：没写任何「坏数据」，编造照样发生。对策按环节重排：生成前——检索接地，把事实塞进上下文（RAG，后续主题）；生成时——低 temperature/约束解码/要求引用来源；生成后——schema 校验、与权威源对账、关键操作人工确认。「提示写严谨点」只是生成时的一小步，不是全部。

### C6 复攻（弱 → 中，中提示点醒）

弱提示（两边最强论据各说一条）没点醒；中提示（把「理解」定义成可观察行为）点醒。销账：正方最强论据——输出全是训练分布的重组，离开文本没有 grounding；反方最强论据——没见过的任务组合也能做对的泛化，逐字复读解释不了。我的立场重写：把「理解」操作化为行为判据——新场景泛化、多步推理一致性、反事实应答；按这些判据模型部分达标，所以「只是鹦鹉」过强；但没有持续学习与世界交互，「真正理解」也过强；边界条件：按任务判据逐案评估，不做全局断言。「感觉它懂」作废，感觉不是判据。
