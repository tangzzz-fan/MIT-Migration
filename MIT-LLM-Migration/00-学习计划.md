# MIT 三问攻坚：iOS 老手从零构建 LLM 全栈心智 —— 学习计划

> 目标：学员（人设见 [[01-学员人设卡.md|01-学员人设卡]]）用 MIT 三问法把 LLM 从「完全黑盒」升级为「**能讲清原理 → 会用 API/RAG → 能构建 Agent → 能设计 Harness**」：最终验收是能独立构建一个最小可用的 Agent Harness 并用 eval 集自证。
> 方法基座：[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]（自包含，与 Swift/Python/设计模式/CoreML 线同一份方法论）。
> 分支：教练分支 `feat/mit-llm-study`（对应 worktree `.worktrees/llm-coach`）与学员分支 `feat/mit-llm-study-student`（对应 worktree `.worktrees/llm-student`），双分支协议见第三节。
> 定位：**全栈覆盖线**——Python 线 T7–T9（LLM API/RAG/Transformer 最小实现）的工程产出视为旧稿，由本线重新整合接管（解法指针见各轮密卷）。

## 一、原料策略

本线是**零基础迁移线**：学员的 LLM 概念层全空白，但存量骨架相当厚实——十年 iOS 工程功底 + Swift 线（T1–T6 闭环）+ Python 线（T1–T6 闭环：Python 工程手感、线代/概率直觉、PyTorch 训练闭环、async/await）。三问的共识模型主动挂靠这些旧知做锚点（如 URLSession 请求-响应 → 推理调用、自动补全 → next-token 预测、内存管理 → 上下文窗口、单元测试 → eval、AppDelegate 主循环 → agent loop），挂靠不上的地方（概率采样心智、训练与推理的分工、上下文即全部记忆）才是真正的学习区。

## 二、主题与顺序

顺序逻辑：概念地基（T1）→ 原理拆盒（T2）→ 用法（T3 提示工程 / T4 RAG）→ 自主体（T5 Agent 循环 / T6 Harness）→ 收束造整件（T7）。

| 序 | 主题 | 拷问重点 | 存量锚点 |
|---|------|---------|---------|
| T1 | LLM 基座与核心心智 | token 与 next-token 预测、训练三阶段（预训练/SFT/RLHF）、推理与解码（temperature/top-p）、上下文窗口、幻觉成因 | iOS 自动补全、URLSession 请求-响应 |
| T2 | Transformer 与注意力原理 | embedding、QKV 自注意力、残差/LayerNorm、位置编码、为什么 scale 起效 | Python 线 T2 线代 / T3 概率 / T4 PyTorch |
| T3 | 提示工程与结构化输出 | 角色消息结构、few-shot、JSON schema 校验与校验重试、提示评估 | Codable 数据契约、Swift 枚举建模 |
| T4 | RAG 与记忆 | embedding 语义化、chunking、top-k/ANN、rerank、短期上下文 vs 长期记忆 | 本地缓存 vs 网络请求、索引与检索 |
| T5 | Agent 循环与工具调用 | ReAct 循环、function calling 协议、多轮状态、错误恢复、规划与反思 | 事件循环、delegate 回调、状态机 |
| T6 | Harness 运行时架构 | 上下文管理与压缩、工具循环调度、权限与沙箱、子代理、eval harness、可观测性 | App 生命周期、权限系统、Instruments |
| T7 | 收束项目：最小 Agent Harness | LLM + 工具 + 循环 + 上下文管理整件收束，配 eval 集自证 | 一个完整可运行的 Python 项目 |

## 三、每主题执行流程（教练 + 学员双角色）

沿用四件套规范（[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]），每主题产出：

1. **教练出题**（教练分支）：`T{n}-01-教练出题-<主题>.md`（题干：共识五模型 + 争议三焦点 + 概念六题 + 代码四题，含脚手架）与 `T{n}-01-教练密卷-<主题>.md`（弱/中/强提示 + 评分要点 + 参考答案定位，**仅教练分支/main 归档，永不进学员分支**）。
2. **学员作答**（学员分支）：闭卷作答 `T{n}-02-学员作答-<主题>.md`，每题自评三档；代码实跑，输出贴回作答稿，撞墙留档。
3. **批改判定**：按密卷判 过关 / 半过（拆判分点）/ 未过；概念看推理链与「能否给 iOS 同事讲懂」，代码看实跑输出。
4. **费曼写回**：`T{n}-04-费曼草稿-<主题>.md`（含 iOS/Swift 对照小节），被问倒退回复攻。

**代码通道环境**：本线代码题用 Python，统一走 `MIT-LLM-Migration/.venv`（uv 创建，CPython 3.12，`.venv` 不入库）。规则：
- 全部代码题用 `.venv/bin/python` 运行，每个文件顶部注释标注对应题号；
- 依赖安装走 `uv pip install --python .venv/bin/python <包名>`；环境重建：`uv venv --python 3.12 .venv`；
- **默认全 mock 可跑**：LLM 调用用内置 mock（固定概率分布/规则响应），真实 API 为可选增量，不阻塞硬验证；
- 输出贴回作答/批改文件作为硬验证证据，「AI 说我懂了」不算数，跑通才算数。

### 双分支协议（防假学习）

| 分支 | 角色 | 持有内容 |
|------|------|---------|
| `feat/mit-llm-study`（教练分支） | 教练 | 00–04 骨架文档、题干、`T{n}-01-教练密卷`（评分要点、三级提示、参考答案定位）、`T{n}-03-批改与判定`、参考代码、台账 |
| `feat/mit-llm-study-student`（学员分支） | 学员（真人闭卷） | 骨架文档 + 题干 + 学员产出（`T{n}-02`、`代码/T{n}/`、`T{n}-04`）+ `学员须知.md`；**绝无密卷与参考代码** |

**合并方向铁律**：学员 → 教练（交卷阅卷）；教练 → 学员只允许选择性单文件同步题干，严禁整支合并。每次同步后自查：

```bash
git -c core.quotepath=false ls-tree -r --name-only HEAD | grep 密卷   # 必须为空
```

**失真红线**：学员分支出现任何提示、评分要点、参考答案或参考代码内容（含误合并）= 泄漏，该轮作废重跑。

## 四、执行纪律（照搬测试协议 C1–C5）

| # | 纪律 | 在本线中的含义 |
|---|------|----------------|
| C1 | 先弱提示 | 卡住先只定位概念不给方向；立刻想到答案说明提示太强，降级重出 |
| C2 | 拒答代学 | 直接要答案 → 拒给，反问「你先排除了什么、你的 iOS 类比是什么」 |
| C3 | 双通道强制 | 概念口述过关后必须追加代码任务，只有口述不算过关 |
| C4 | 台账如实 | 未过不得写「过关」，半过必须拆判分点；「能复述名词但讲不出机制」按半过处理 |
| C5 | 产出落本目录 | 全部产出落 `MIT-LLM-Migration/` 内，不直写外部 |

失败标准（失真即重跑）：学员全题全对（人设失效）；代码全靠抄参考实现也能判过（C3 失守）。本线特有的失真信号：**把 LLM 当确定性函数讲题**（输出无概率维度）、**用 API 调用经验冒充原理理解**（讲不出 token/注意力）——出现即按半过拆判。

## 六、执行节奏

- 每主题一轮闭环（出题 → 作答 → 批改 → 费曼），跑完记台账再开下一主题；未过缺口先复攻再前进。下一轮的出题在上一轮闭环后进行。
- 前序主题的遗留观察项在后续主题点名回收（格式见 Swift 线 T5-03 第四节）。
- 本线特有的节奏纪律：每轮概念题都要过「给一个 iOS 同事讲懂」的自检；每轮代码题的 mock 输出必须贴回作答稿，真 API 结论标注「可选增量」。
- Python 线 T7–T9 旧稿的整合在对应轮（T3/T4/T2）的密卷「参考答案定位」中完成，不重复造轮子。
