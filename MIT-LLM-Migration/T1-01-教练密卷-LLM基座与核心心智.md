## 一、概念题：提示梯与评分要点

### C1 什么是 token？为什么 LLM 不是「按字处理」文本？
- 弱提示：先想 iOS 键盘的「联想单位」——它联想的是一个字符还是一个词？LLM 的处理单位跟谁更像、又差在哪？
- 中提示：tokenizer 是文本与模型之间的翻译层：把任意文本切成词表里的单元。「好」是一个单元，「strawberry」可能被切成多个单元——模型看到的是单元序列，不是字母序列。
- 强提示：token 是词表中的离散单元（BPE 把高频片段合并成单元）；中文一字常一 token、英文常见词一 token 而长词拆多段，所以同一语义中英文 token 数差异大；「数错 r」因为模型从不逐字母看——它看到的是 token 序列，strawberry 在词表里可能就是一个整体单元，字母级信息在切分时被抹掉了。
- 评分要点：
  - 死记硬背典型：「token 就是单词。」（说不出与字符/词表的关系，解释不了中英差异）
  - 真懂特征：讲清「切分单位 ≠ 字符也 ≠ 单词」，能用 BPE 的「高频片段合并」解释中英差异与数错字母现象。
- 参考答案：token 是 tokenizer 按词表切出的单元，是模型真正读写的离散符号；切分由统计规律（BPE 合并高频子串）决定，与语言学单位无关。中英 token 数差异来自词表构成与切分粒度；字母级任务失败因为字母信息在 tokenize 阶段就被抹掉了。

### C2 你第二次问同一个问题，模型「内部」发生了什么？
- 弱提示：用 iOS 的发布流程想——「改代码」和「跑 App」是同一件事吗？模型在哪一步「改自己」，哪一步「只是跑」？
- 中提示：训练 = 用海量数据反复调权重（发生在发布前的机房里）；你调 API 时权重早已冻结，只做前向计算。「聊久了更懂我」里的「懂」来自哪里——是权重变了，还是别的什么变长了？
- 强提示：① 训练在离线阶段完成，推理阶段权重不变；② 模型无状态，「记得」= 全部历史还在本次请求的上下文里，昨天没带进来就等于没发生；③ 「越来越懂我」对的部分：上下文里积累了你的偏好与历史（产品把历史拼进去）；错的部分：模型本身没有发生任何学习，换一个新会话一切归零。
- 评分要点：
  - 死记硬背典型：「模型会持续学习用户习惯。」（训练/推理混为一谈）
  - 真懂特征：能区分训练期与推理期，把「记忆」归因到上下文而非权重，指出「聊久了更懂」的产品机制（历史拼接）与错误心智（模型在学习）。
- 参考答案：推理 = 冻结权重上的前向计算 + 解码采样；无状态意味着每次请求自包含；一切「记忆」都是上下文工程，不是模型学习。

### C3 为什么同一个 prompt 每次输出不一样？temperature 和 top-p 各管什么？
- 弱提示：M1 说模型输出的是「概率分布」——从一个分布里得到一个结果，这步叫什么操作？这步能不能每次都一样？
- 中提示：采样（按分布随机抽取）是随机性的唯一来源；greedy（总取最大）是确定性的特例。temperature 改分布的形状，top-p 改候选集的大小——分别怎么改？
- 强提示：随机性产生于「从 next-token 分布中采样」这一步。temperature：除在 logits 上再 softmax——T<1 让分布更尖（更保守），T>1 更平（更发散）；top-p：按概率降序累积到 p 截断，只在核内重归一化采样。工程判断：结构化输出/代码/事实问答 → 低 T（要确定性）；文案/头脑风暴 → 高 T（要多样性）。
- 评分要点：
  - 死记硬背典型：「temperature 越高越有创意。」（讲不出采样与分布形状，给不出工程边界）
  - 真懂特征：指出随机性在采样步，讲清 T 与 p 各自作用于分布的哪个维度，并给出按任务选参的判断。
- 参考答案：随机性内建于采样；T 调分布锐度、p 调候选截断，两者正交可叠加；确定性输出是 greedy/T→0 的特例。

### C4 上下文窗口是什么？「模型记得我」的真相是什么？
- 弱提示：HTTP 请求是无状态的——服务器怎么「记得」登录态？LLM 的「记得」跟这个像不像？
- 中提示：窗口 = 一次推理能看见的全部 token 预算（输入+输出共用）。超窗时客户端/API 会截断或报错——被截掉的部分对模型来说等于不存在。长对话贵慢的原因，除了计费，还有计算层面的——注意力跟长度什么关系？（T2 回收）
- 强提示：① 无状态 → 每次必须带全历史，「记忆」= 历史仍在窗口内；② 超窗 → 截断（丢旧信息）或报错；③ 贵慢双重原因：token 计费 + 注意力计算随序列长度增长（T2 会证明是平方级）。iOS 类比：窗口像一次请求的内存上限/栈帧——断裂处：内存释放后数据还在磁盘，窗口截断后信息对模型就是永久消失（除非外部存储，T4 伏笔）。
- 评分要点：
  - 死记硬背典型：「窗口就是模型的记忆容量。」（讲不清无状态与截断后果）
  - 真懂特征：讲透「无状态 → 全量携带 → 截断即遗忘」链条，给出类比及断裂处，提到计算成本随长度涨（可只定性）。
- 参考答案：窗口是硬预算：输入输出共享、超窗即截断、成本随长度涨；「记得」完全是上下文拼接的产物。

### C5 幻觉为什么不是 bug？工程师该怎么「为幻觉设计」？
- 弱提示：M1+M3：模型的工作是「给出最像人话的下一个 token」——它的工作目标里有没有「真」这个字？
- 中提示：bug 是「实现偏离了设计目标」；如果目标本来就是流畅续写而非事实正确，那编造是偏离还是忠实执行？知识缺失时分布仍然要给出一个答案——分布里最高概率的是什么样的内容？
- 强提示：机制成因：目标是最大化「像训练数据的续写」，没有真值校验环节；知识缺失时，模型照样产出分布上最流畅的续写，于是编造得自信且流畅。工程对策（按环节）：生成前——检索接地（RAG 把事实塞进上下文，T4）；生成时——约束解码/低 temperature/要求引用来源；生成后——结构化校验、与权威数据源对账、人工确认关键操作（T3/T6）。
- 评分要点：
  - 死记硬背典型：「幻觉是训练数据有噪声导致的，清洗数据就能解决。」（归因错误，无对策分环节）
  - 真懂特征：从目标函数推出幻觉的必然性，对策按生成前/时/后分环节且能落到本线后续主题。
- 参考答案：幻觉 = next-token 目标在知识缺失域的忠实执行，是结构性的；工程姿态是「为幻觉设计」：检索接地 + 输出约束 + 事后校验三层防线。

### C6 「LLM 只是随机鹦鹉」——有边界的立场
- 弱提示：先别站队——正方最强论据和反方最强论据各是什么？你能同时把两边说到让对方点头吗？
- 中提示：正方：输出全部来自训练分布的重组，没有 grounding（离了文本没有世界模型）。反方：涌现的泛化能力（没见过的任务组合也能做对）很难用「逐字复读」解释。「理解」这个词本身要不要先定义成可观察的行为判据？
- 强提示：合理立场示例：把「理解」操作化为行为判据（新场景泛化、多步推理一致性、反事实应答）——在这些判据下模型部分达标，所以「只是鹦鹉」过强；但缺乏持续学习与世界交互，「真正理解」也过强；边界条件：按任务判据逐案评估，不做全局断言。诉诸意识/灵魂 = 没有判据 = 未过。
- 评分要点：
  - 死记硬背典型：直接站一边且给不出对方最强论据；或「见仁见智」式滑头。
  - 真懂特征：双方最强论据 + 自己的立场带明确边界条件 + 可观察判据。
- 参考答案：争议题无标准答案，判「立场有无边界」：能给出行为判据与适用条件即过关。

## 二、争议焦点参考立场

- **D1 scaling vs 工程**：合理立场是「scaling 是底层规律但工程是性价比杠杆」——先 RAG/工具/eval，模型升级是最后手段；站死任何一边而无预算/任务边界 = 半过。
- **D2 推理模型默认开**：合理立场是「按任务难度与延迟/成本预算分层」——多步难题开、简单任务关；「一律最强/一律不开」都缺边界。
- **D3 幻觉可治**：合理立场是「可压制不可根除」——三层防线把幻觉压到业务可接受；声称「彻底治好」或「完全不能用」都走极端。

## 三、代码题：评分要点与提示

### Q1 tokenizer 体验
- 评分要点：encode/decode 往返无损（assert 通过）；中英 token 数对比有真实输出；BPE 差异与中文费 token 的解释写在注释里且机制正确。
- 参考要点：字符级 vocab 下中文一字一 token、英文一字母一 token（英文句子反而更长）——这正是引出「真实 BPE 会把高频英文子串合并、中文合并机会少」的认知冲突点；解释必须落到「切分粒度由词表与统计决定，不由语言直觉决定」。
- 参考代码：`代码/T1/Q1-字符级tokenizer.py`（教练分支）。

### Q2 mock 概率采样器
- 评分要点：三种解码实现正确；频率表实跑输出贴回；三条验证结论（greedy 恒定/T 越高越平/top-p 只在核内）都有数据支撑；能讲 top-p 的「降序累积截断 + 重归一化」。
- 参考要点：temperature 作用在 logits（`p_i^(1/T)` 后归一化即可）；top-p 先排序累积到 ≥p 截断再归一化；T=2.0 时低频候选频率显著上升、p=0.7 时「不好说/也许」出现率被压制，是判分的关键观察点。
- 参考代码：`代码/T1/Q2-mock概率采样器.py`（教练分支）。

### Q3 上下文窗口实验
- 评分要点：截断策略实现为「保留最近」（丢弃内容打印可见）；budget_report 三字段齐全；10 轮对话演示第 9 轮遗忘第 1 轮信息，输出能看出「遗忘」发生的具体轮次。
- 参考要点：mock 回复只需证明「模型只能看到窗口内的历史」——如让 mock 复述/引用早期消息，超窗后引用失败即为遗忘证据；预算计算要说明「输入+输出共享窗口」。
- 参考代码：`代码/T1/Q3-上下文窗口实验.py`（教练分支）。

### Q4 幻觉最小复现
- 评分要点：知识库命中/未命中两条路径都实跑；100 次采样统计表含命中率/编造率；「编造答案同样自信」有输出证据；一句话结论点题（不会说不知道是目标函数使然，不是缺陷）。
- 参考要点：编造路径要从固定分布里抽「自信句式」（如「根据权威资料，X 是 Y」），让置信度与知识命中与否无关——这正是「流畅优先」的 mock 化；若学员给 mock 加了「不知道」分支，追问「真实模型里这个分支从哪来」（训练/提示，非天生）。
- 参考代码：`代码/T1/Q4-幻觉最小复现.py`（教练分支）。

## 四、使用纪律

- 判分只认证据：概念看机制推理链与「给 iOS 同事讲懂」，代码看实跑输出；撞墙记录须有真实报错。
- 失真自查：学员全题全对 → 人设失效（零基础线首轮应有未过/半过）；把 LLM 当确定性函数讲题还判过 → 心智失守需重跑；代码全靠抄参考实现也能判过 → 双通道失守。
