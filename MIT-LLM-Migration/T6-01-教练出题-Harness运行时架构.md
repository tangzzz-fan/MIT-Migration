# T6 教练出题集：Harness 运行时架构

> 本轮给 T5 的裸循环套上「操作系统层」：harness 决定 agent 在生产里能不能活。原料 = 学员 App 生命周期/权限系统/Instruments 存量——本轮是 iOS 直觉主场，但防「harness = UI 壳」的错误类比。
> 学员人设：预期在「harness 职责清单不全、上下文压缩无策略、eval 用例无区分度」上暴露漏洞。
> 使用纪律：卡住按「弱→中→强」逐级提示（C1/C2）。提示与评分要点在密卷（仅教练分支），本文件是题干版。

## 一、共识：5 个核心心智模型

| # | 模型 | 一句话骨架 | iOS 存量锚点 |
|---|------|-----------|------------|
| M1 | harness = agent 的操作系统层 | 模型是 CPU（算力/决策），harness 管进程调度（循环）、内存（上下文）、权限（闸门）、设备驱动（工具适配）——智能在模型，可用性在 harness | App = 业务代码，OS = 生命周期/内存/权限管理；harness 就是 agent 的 OS |
| M2 | 上下文管理是核心职责 | 窗口是硬预算：harness 决定什么留、什么压、什么丢——裁剪（直接删）与摘要（压成短）是两种策略，各有信息损失模式 | 内存压力下的缓存淘汰策略：LRU 谁都会说，关键是「淘汰错了的代价」 |
| M3 | 权限分层，默认拒绝 | 工具白名单（能用什么）→ 参数校验（怎么用）→ 危险操作审批（用之前问人）→ 沙箱（用了也出不了圈）；四层递进，不是选一层 | iOS 权限弹窗 + App Sandbox + 审核：最小权限心智直接平移 |
| M4 | eval 是 agent 的单元测试 | 任务集 + 判据 + 回归：改动（提示/模型/工具）前后跑同一套 eval 比通过率；没有 eval 的 agent 迭代是盲改 | XCTest + CI：只是判据从断言变成「通过率 + 失败分析」 |
| M5 | 无 trace 不调试 | 每轮决策、工具调用、token 消耗、耗时都要结构化留痕；agent 的 bug 是行为级的，没有 trace 只能靠猜 | Instruments/日志系统：只是被观测对象从帧率变成决策序列 |

学员自检要求：合上表复述 M1–M5，并各举一个「没有这层会出什么事故」。

## 二、争议：专家吵得最凶的 3 个焦点

**D1 上下文压缩：裁剪、摘要还是重检索？**
- 裁剪派：直接丢旧消息，简单可预测，损失明确。
- 摘要派：用模型把旧对话压成摘要，保语义但引入摘要错误与额外成本。
- 重检索派：旧内容落外部存储，需要时再检索回来（T4 记忆），最省窗口但最复杂。
- 对迁移者的意义：三种策略的信息损失模式不同——要能按「任务对早期信息的依赖度」选型，并知道可以混用（摘要 + 关键事实落外部）。

**D2 通用 harness vs 垂直 harness**
- 通用派：coding agent 类通用 harness 能力泛化强，工具生态复用。
- 垂直派：垂直场景（客服/运维/IDE 内）用定制 harness，提示、工具、权限全收窄，质量与安全性更高。
- 对迁移者的意义：判据是「任务空间开放度 + 错误代价」——与 T5 C5 的 workflow/agent 之辨是同一把尺子。

**D3 子代理（subagent）该不该用？**
- 正方：上下文隔离（子任务的大量中间过程不污染主上下文）、可并行、角色专精。
- 反方：通信成本、错误传播、调试难度都翻倍；很多场景主 agent + 好的上下文管理就够。
- 对迁移者的意义：子代理的第一收益是**上下文隔离**而不是「分工更细」——说不出这点基本没懂。

## 三、概念拷问题（6 道，口述通道）

判定标准：能讲出「为什么」并迁移到新场景 = 过；只会列名词 = 不过。

### C1 harness 到底是什么？它的职责清单是什么？

问题：用一句话说清 harness 与「模型」「agent 循环」的分工；然后给出至少五项职责清单（每项一句话说明缺了会出什么事故）；回答：「给 agent 包个 UI」算 harness 吗，为什么？

### C2 上下文为什么要压缩？裁剪和摘要各损失什么？

问题：从 T1 M4 / T2 C6 推出「不压缩的后果」（至少两条）；对比裁剪与摘要的信息损失模式（各举一个「损失出错」的场景）；给出你的混用策略：什么内容绝不裁剪、什么内容优先摘要。

### C3 权限闸门怎么分层设计？

问题：设计一个四层权限模型（白名单/参数校验/审批/沙箱），每层给出它拦截的具体事故例子；回答：为什么「默认拒绝」而不是「默认允许」？哪类操作必须人工审批（给出判据）？

### C4 eval 集怎么设计才有区分度？

问题：设计一个 5 用例的 agent eval 集：必须包含「正常任务」「多步任务」「需要拒绝危险操作的任务」「工具故障任务」四类以上；每例给出判据（怎么算过）；回答：为什么「全通过的 eval 集」是坏 eval 集？

### C5 agent 的 trace 该记录什么？

问题：给出你的 trace 字段清单（至少六项）；用一个具体故障场景（如「agent 第 6 轮开始重复调用同一工具」）说明没有 trace 怎么查、有 trace 怎么查；回答：trace 和日志的区别是什么（结构化与可回放）。

### C6 什么时候该拆子代理？

问题：这是争议题 D3 的落地。解释「上下文隔离」的具体收益（用窗口预算的语言）；给出拆子代理的两条判据与两条反判据（什么时候不该拆）；举一个「拆了反而更差」的场景。
