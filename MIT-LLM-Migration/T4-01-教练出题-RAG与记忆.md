# T4 教练出题集：RAG 与记忆

> 本轮解决 T1 M5（幻觉）的工程解法主线：把事实塞进上下文而不是指望权重。原料 = 学员缓存/索引工程存量 + T2 embedding 几何 + Python 线 T8 已练旧稿（整合接管）。
> 学员人设：预期在「RAG 当搜索引擎、以为检索到的内容被模型学会、chunking 无策略」上暴露漏洞。
> 使用纪律：卡住按「弱→中→强」逐级提示（C1/C2）。提示与评分要点在密卷（仅教练分支），本文件是题干版。

## 一、共识：5 个核心心智模型

| # | 模型 | 一句话骨架 | iOS 存量锚点 |
|---|------|-----------|------------|
| M1 | 语义检索 = 几何近邻 | 文本变向量后，「相关」= 向量距离近；同义改写不改变近邻关系，关键词匹配则直接失联 | 像按内容哈希找资源 vs 按文件名找：一个认内容一个认字面 |
| M2 | chunking 决定检索上限 | 检索的最小单位是切出来的块：切太大混入噪声、切太小丢上下文，边界处信息必然受损——检索质量问题一半出在切分 | 像分页加载的页大小：粒度是权衡，不是常量 |
| M3 | RAG 管道五环，错误逐级传播 | 切分 → 向量化 → 检索 → 组装 → 生成：每一环都有独立失败模式，评估要按环定位（召回坏 vs 生成坏是两回事） | 像网络管线：DNS/连接/解码/渲染各环各的错，先定位再修 |
| M4 | 注入 ≠ 学习 | 检索来的内容只活在本次上下文里：权重不动、会话结束即消失；「给模型喂文档」不是训练 | 像运行时读配置文件 ≠ 改二进制（T1 M2 回收） |
| M5 | 记忆分层 | 短期记忆 = 上下文窗口（贵、小、会话级）；长期记忆 = 外部存储 + 按需检索（便宜、大、跨会话）；产品「记得你」= 分层的组合拳 | RAM vs 磁盘 + 按需加载：客户端内存管理心智直接平移 |

学员自检要求：合上表复述 M1–M5，并回答「我的 App 想『记住』用户偏好，该用哪一层、为什么」。

## 二、争议：专家吵得最凶的 3 个焦点

**D1 上下文窗口越来越大（百万级），RAG 还有必要吗？**
- 正方（长上下文派）：全文塞进去，省掉切分/检索两环的错误，模型还能看到全貌。
- 反方（RAG 派）：成本随长度涨（T2 C6 的 O(n²)）、长文中部信息常被稀释（lost in the middle）、知识更新仍需要外部化；大窗口是互补不是替代。
- 对迁移者的意义：这是「容量 vs 成本 vs 精度」的三角权衡——给得出边界条件（什么规模下全文塞、什么规模下必须检索）才算懂。

**D2 知识注入用 RAG 还是微调？**
- RAG 派：知识更新频繁、需要溯源引用、数据敏感不能进权重 → RAG。
- 微调派：要改的是行为/风格/领域语言习惯而非事实 → 微调；且「教模型事实」用微调本就不可靠。
- 对迁移者的意义：判据是「变的是知识还是行为」——这与 T3 C6 的决策树是同一把尺子。

**D3 向量检索要不要和关键词检索混用（hybrid）？**
- 纯向量派：语义统一表示，关键词是过时的补丁。
- 混合派：专有名词/编号/代码标识符恰恰是 embedding 弱项，BM25 类关键词检索正好补位；加一路 rerank 融合。
- 对迁移者的意义：知道各自的失败案例（向量搜不到精确编号、关键词搜不到同义改写）比站队重要。

## 三、概念拷问题（6 道，口述通道）

判定标准：能讲出「为什么」并迁移到新场景 = 过；只会搭管道 = 不过。

### C1 为什么关键词搜索不够？语义检索「语义」在哪？

问题：构造一个具体例子：用户查询与答案文档**没有一个字重叠**但仍然相关（同义改写）；解释关键词检索与向量检索在这个例子上的行为差异；再给出一个反例——什么查询是关键词检索反而更靠谱的。

### C2 chunking 切大切小各会出什么问题？

问题：分别给出「块太大」与「块太小」的失败场景（各一个具体例子）；解释重叠（overlap）在缓解什么、代价是什么；最后给出你选块大小的可操作判据（不许只说「看情况」）。

### C3 RAG 五环，哪一环最容易成为瓶颈？怎么定位？

问题：说出五环（切分/向量化/检索/组装/生成）各自的典型失败模式；然后回答：用户抱怨「回答不对」时，你按什么顺序排查、每步看什么证据（要能区分「没检索到」与「检索到了但没用好」）。

### C4 RAG 是训练吗？「喂文档」之后模型发生了什么？

问题：明确回答检索内容去了哪里（权重还是上下文）、会话结束后还在不在、换一个新会话会怎样；再推一步：这决定了 RAG 系统的哪些工程属性（知识更新成本、溯源能力、数据隔离）。

### C5 上下文窗口就是记忆吗？长期记忆应该怎么建？

问题：用 T1 M4（窗口 = 全部记忆）推出「纯上下文记忆」的三个限制；然后设计一个分层记忆方案：什么信息留在上下文、什么存外部、什么时候触发写回与检索。用你的 iOS 内存管理经验做类比并指出断裂处。

### C6 检索质量怎么评估？hit@k 和 MRR 各测什么？

问题：解释两个指标的定义与差异（一个测「在不在前 k」、一个测「排多前」）；设计一个 10 查询的检索评估集骨架：每条要准备什么（查询 + 期望命中的块）、为什么需要「期望不命中」的用例。
