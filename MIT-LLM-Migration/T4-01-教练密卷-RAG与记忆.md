## 一、概念题：提示梯与评分要点

### C1 关键词不够，语义在哪
- 弱提示：想想你搜「怎么让列表滚动更流畅」，文档标题是「UITableView 性能优化」——有一个字匹配吗？
- 中提示：关键词匹配的是字面共现；向量匹配的是语境分布（T2 M1：语境相近 → 向量近邻），改写不改语义所以不改近邻。
- 强提示：同义例：查「如何缓解焦虑」对「减压的方法与技巧」——零字重叠但向量近。反例：错误码/订单号/SwiftUI 的 `.task(id:)` 这类精确标识符——embedding 空间里它们没有可靠的近邻结构，关键词/精确匹配反而稳（D3 混合检索的动机）。
- 评分要点：正反两例都要有且解释机制；只给同义例 = 半过。
- 参考答案：语义 = 分布几何；检索选型按「查询是语义意图还是精确标识」分流。

### C2 chunking 大小权衡
- 弱提示：分页加载页大小选 1 条和选 1000 条各会怎样？
- 中提示：太大：命中块里答案占比低，组装进上下文稀释预算、还可能带入矛盾信息；太小：答案被切碎（跨句推理断裂）、检索出很多碎片要合并。
- 强提示：重叠缓解「答案恰好骑在切缝」的丢失——让边界内容在相邻块里再出现一次；代价是存储翻倍段与重复命中（去重/融合要处理）。可操作判据：按「答案的典型长度 + 所需上下文句数」定块长，用评估集（C6）实测不同切分的 hit@k 再定，不靠拍脑袋。
- 评分要点：两个方向的失败场景具体化 + 重叠的代价 + 可测判据 = 过；「看情况」无判据 = 半过。
- 参考答案：chunking 是检索的采样定理：粒度决定可检索信息的最小单位（M2）。

### C3 五环定位
- 弱提示：网络请求失败你先看什么——DNS、连接、响应体、解析？RAG 同理按环看。
- 中提示：典型失败：切分环（答案被切碎/不在任何块）、向量化环（query 与文档的向量空间不一致，如用了两个不同 embedding）、检索环（top-k 太小/相似度阈值不当）、组装环（检索到了但提示模板截断或淹没）、生成环（检索正确但模型没采用或改写错）。
- 强提示：排查顺序：先看检索环证据（打印 top-k 命中块：期望块在不在）——不在 → 回溯切分/向量化；在 → 看组装与生成（把命中块直接贴给模型试答，区分「没用好」与「检索没到」）。评估指标按环拆：检索环用 hit@k/MRR（C6），生成环用端到端判据。
- 评分要点：五环失败模式 ≥4 个 + 「检索证据先行」的定位顺序 = 过；只会端到端重跑 = 半过。
- 参考答案：M3 的落地 = 每环可观测、可独立评估。

### C4 RAG 不是训练
- 弱提示：T1 M2——推理时权重动不动？检索来的文档去了哪？
- 中提示：文档只进本次请求的上下文，会话结束即蒸发；权重零改动。
- 强提示：工程属性推导：知识更新 = 换文档库（秒级，不需重训）；溯源 = 可标注引用块（幻觉防线，T1 D3 回收）；数据隔离 = 按权限过滤检索结果（不训练就不会「漏」进别的用户）。说「RAG 让模型学会了文档」= 心智错误。
- 评分要点：权重/上下文分清楚 + 推出 ≥2 条工程属性 = 过。
- 参考答案：RAG = 运行时的知识外挂，不是学习（M4）。

### C5 记忆分层
- 弱提示：纯上下文记忆的三个限制——从 T1 M4 推：容量（窗口上限）、成本（每轮全量携带）、寿命（会话结束清零）。
- 中提示：分层 = 热数据留上下文（当前任务相关）、冷数据存外部（偏好/历史事实），用「写入（对话中提取）+ 检索（新会话按 query 拉回）」两个动作连接。
- 强提示：方案要素：写回触发（每轮抽取 or 显式记忆指令）、存储形态（KV / 向量库）、检索时机（新会话开始 or 命中意图时）、失效与冲突（新偏好覆盖旧的）。iOS 类比：RAM（上下文）vs Core Data（外存）；断裂处：内存数据 App 重启丢失是 bug，上下文清零是**设计**——LLM 的「持久化」完全靠外挂。
- 评分要点：三限制 + 写回/检索两动作 + 类比断裂处 = 过。
- 参考答案：长期记忆是工程构件不是模型能力（M5）。

### C6 hit@k 与 MRR
- 弱提示：一个测「有没有进前 k」，一个测「排在第几」——哪个对「首位命中」敏感？
- 中提示：hit@k = 前 k 里含期望块的比例（0/1）；MRR = 期望块首次出现排名的倒数平均——首位 1.0，第二位 0.5，能区分「检索到但排太后」。
- 强提示：评估集骨架：10 查询各配期望命中块（人工标注），加「期望不命中」用例（库外查询）测误召回——全命中集测不出「什么都召回」的坏检索器。检索是排序问题，所以两个指标互补：hit@k 看召回能力，MRR 看排序质量（组装时排前的块影响更大）。
- 评分要点：定义对 + 互补关系 + 负例用例意识 = 过。
- 参考答案：没有评估集的检索调参都是玄学（呼应 T3 M5）。

## 二、争议焦点参考立场

- **D1 长上下文 vs RAG**：合理立场「三角权衡：小文档全文塞、大库必检索、中间带按成本与 lost-in-the-middle 风险选」；只站一边 = 半过。
- **D2 RAG vs 微调**：合理立场「变知识 → RAG，变行为 → 微调；事实类注入别指望微调」；与 T3 C6 同尺。
- **D3 hybrid 检索**：合理立场「语义查意图、关键词查标识符，融合加 rerank」；能各给一个失败案例即过。

## 三、代码题：评分要点与提示

### Q1 语义 vs 关键词
- 评分要点：mock 向量构造使语义相近文档确实近（注释说明构造逻辑）；同义例与编号反例都打印出预期差异；能解释反例为什么反。
- 参考解法定位：`MIT-Python-Migration/代码/T8/`（8.1）——对拍用，不许抄。

### Q2 切分器边界效应
- 评分要点：关键信息骑缝的构造刻意且注释说明；两种切分的检索结果对比打印；重叠的收益（找回）与代价（重复/存储）都写清。
- 参考要点：「丢失」的证据 = 无重叠时 top-k 命中块不含关键句，有重叠时含。

### Q3 迷你 RAG
- 评分要点：五环中间产物全打印；库内 3 查询照实、库外 2 查询编造且带来源标记；能指出两种幻觉路径（检索失败 vs 知识缺失）的差异。
- 参考解法定位：`MIT-Python-Migration/代码/T8/`（8.3）——对拍用，不许抄。

### Q4 记忆分层实验
- 评分要点：A/B 两系统同对话跑通；第 11 轮差异打印可见（A 遗忘、B 命中）；写回/检索触发条件写清并对回真实组件（记忆抽取/向量检索）。

## 四、使用纪律

- 判分只认证据：概念看「检索/记忆机制」的推理链，代码看每环证据与对比输出；「管道跑通了但讲不清哪环起作用」= 半过。
- 失真自查：学员全题全对 → 人设失效；说「模型学会了文档」「RAG 就是搜索」还判过 = 心智失守。
