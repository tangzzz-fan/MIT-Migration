> 定位：本文件是 [[00-学习计划.md|学习计划]] 代码通道的**工程载体**——MIT 三问负责拷问与判定纪律，本路线的迭代项目负责提供「可运行的完整骨架」。各 Phase 与 T1–T7 的绑定见 [[00-学习计划.md#七、代码通道载体绑定|学习计划第七节]]。

## Agent 角色定义

**身份**: 从 iOS/Swift 转向 LLM/Agent 方向的开发者 Agent
**背景**: 十年 iOS 工程经验；Python 线 T1–T6 闭环（工程手感、线代/概率直觉、PyTorch、async）；LLM 概念层零基础。
**目标**: 以 MIT 学习方式从零建立 LLM 全栈心智——原理可讲（token/注意力/解码）、用法可控（提示工程/RAG）、Agent 可造（工具循环）、Harness 可设计（上下文管理/权限/eval），最终交付一个最小可用的 Agent Harness。
**约束**: 所有学习必须通过可运行的代码项目验证，禁止纯理论阅读；默认全 mock 可跑（内置 mock LLM），真实 API 为可选增量；每个阶段必须有明确的可交付物，且附「iOS 对照」直觉说明。

## MIT 学习方式核心原则

1. **项目驱动 (Project-Based)**: 每个知识模块都绑定一个可运行的项目迭代，而非孤立练习；全线共用一个逐轮生长的载体——**mini-agent-harness**。
2. **快速迭代 (Rapid Iteration)**: 每个项目从 MVP 到优化版控制在 3-5 个迭代周期内，每个周期有明确的功能增量。
3. **从错误中学习 (Learning by Debugging)**: 主动制造边界场景（temperature=0 vs 采样、超窗截断、工具调用死循环、上下文污染），通过运行报错与断言失败反向推导机制。
4. **第一性原理 (First Principles)**: 不满足于「怎么调 API」，必须追问「为什么这样设计」——从 next-token 预测的底层约束推导解码参数、上下文管理、Agent 循环的形态。
5. **迁移对比 (Migration Lens)**: 始终对比 iOS/Swift 中的等效心智（无状态请求、内存管理、权限系统、单测），明确范式差异（确定性函数 vs 概率采样、持久存储 vs 上下文窗口、代码分支 vs 模型决策），避免用客户端思维套 LLM 系统。

## 学习路线图

### Phase 1: LLM 基座体验 (Week 1，T1 载体)
**核心目标**: 用最小实验把「token / 概率采样 / 解码参数 / 上下文」从名词变成可观察现象。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 1.1 | 字符级 tokenizer 体验 | 简易 BPE/字符切分器：同一句话的 token 数统计、中英文对比 | token、词表、编码单元 ≠ 字符 |
| 1.2 | mock 概率采样器 | 给定固定概率分布，实现 greedy / temperature / top-p 三种采样并对比输出分布 | next-token 概率、解码策略、随机性来源 |
| 1.3 | 上下文窗口实验 | mock 模型带窗口上限：超窗截断的可观察复现 + token 预算计算器 | 上下文窗口、截断、预算 |
| 1.4 | 幻觉最小复现 | mock「知识缺失时按概率编造」：展示幻觉是采样结构性产物而非 bug | 幻觉成因、置信度缺失 |

**关键对比任务**: iOS 键盘自动补全 vs LLM next-token 预测的对照说明（规模、词表、概率分布的差异）。

---

### Phase 2: Transformer 原理拆盒 (Week 2，T2 载体)
**核心目标**: 把 Transformer 从黑盒拆到矩阵层：embedding → 注意力 → 残差，全部 numpy 可跑。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 2.1 | embedding 直觉实验 | 词向量查表 + 余弦相似度小实验（内置小型词表） | embedding、语义空间 |
| 2.2 | 单头自注意力（numpy） | QKV 计算 + softmax 加权，与 Python 线 T9 参考代码对照 | QKV、注意力权重、缩放 |
| 2.3 | 因果 mask 验证 | 有/无 mask 的注意力矩阵对比，证明「看不到未来」 | 因果性、mask |
| 2.4 | 残差与 LayerNorm 实验 | 加/不加残差的数值稳定性对比 | 残差流、归一化 |

**关键对比任务**: 与 [[../MIT-Python-Migration/代码/T9/|Python 线 T9 参考代码]] 对拍，写「数学存量 → 注意力机制」的挂靠说明。

---

### Phase 3: 提示工程与结构化输出 (Week 3，T3 载体)
**核心目标**: 把「提示」从玄学变成工程：消息结构、few-shot、JSON schema 校验与重试。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 3.1 | 消息结构最小客户端 | mock LLM 的 role/content 消息协议 + system 指令生效验证 | 消息结构、system/user |
| 3.2 | few-shot 实验台 | 0-shot vs 2-shot 的 mock 行为差异对比 | few-shot、示例格式 |
| 3.3 | 结构化输出管道 | JSON 解析 + schema 校验 + 校验失败有限重试（整合 Python 线 T7 Phase 7.4） | 结构化输出、校验重试 |
| 3.4 | 提示评估集 | 10 条用例的提示回归测试 + 两版提示的对比报告 | 提示评估、回归 |

**关键对比任务**: Codable 数据契约 vs JSON schema 校验的对照说明。

---

### Phase 4: RAG 与记忆 (Week 4，T4 载体)
**核心目标**: 把检索补成语义工程：embedding 检索、chunking、迷你 RAG、短期上下文 vs 长期记忆。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 4.1 | 语义检索 demo | 内置句向量（mock embedding）+ 余弦 top-k，对比关键词匹配 | embedding 检索 vs 关键词 |
| 4.2 | 文档切分器 | 固定+重叠 vs 按段落，边界效应对比（整合 Python 线 T8 Phase 8.2） | chunking 策略 |
| 4.3 | 迷你 RAG | 切分→向量化→检索→组装上下文→mock 生成（整合 Python 线 T8 Phase 8.3） | RAG 管道 |
| 4.4 | 记忆分层实验 | 纯上下文 vs 外挂记忆存储的对话保持对比 | 短期上下文、长期记忆 |

**关键对比任务**: iOS 本地缓存（Core Data/文件）vs 上下文窗口的对照：什么是「模型真的记住了」。

---

### Phase 5: Agent 循环与工具调用 (Week 5，T5 载体)
**核心目标**: 构建最小 agent loop：模型决策 → 工具执行 → 结果回填 → 再决策，直到完成。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 5.1 | function calling 协议 | 工具 schema 声明 + mock 模型发出工具调用 + 解析执行 | function schema、调用协议 |
| 5.2 | ReAct 循环 | 思考→行动→观察循环的最小实现，带最大轮数与终止条件 | ReAct、循环终止 |
| 5.3 | 错误恢复 | 工具报错回填后模型重试 vs 直接崩溃的对比 | 错误恢复、观察回填 |
| 5.4 | workflow vs agent 对拍 | 同一任务两版实现：硬编码流程 vs 模型决策循环 | workflow、agent 边界 |

**关键对比任务**: 事件循环/delegate 回调 vs agent loop 的对照；状态机视角画 agent 循环图。

---

### Phase 6: Harness 运行时架构 (Week 6，T6 载体)
**核心目标**: 给 agent loop 套上运行时：上下文管理、权限闸门、可观测性、eval 集。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 6.1 | 上下文管理器 | token 预算内的裁剪/摘要压缩策略 + 超窗前后行为对比 | 上下文压缩、预算 |
| 6.2 | 权限闸门 | 工具白名单 + 危险操作确认门（mock 人工确认） | 权限、沙箱、人工审批 |
| 6.3 | 运行日志与追踪 | 每轮决策/工具调用/token 消耗的结构化 trace | 可观测性、调试 |
| 6.4 | eval 集 | 5+ 任务用例的端到端 eval + 通过率报告 | eval harness、回归 |

**关键对比任务**: iOS 权限弹窗/沙箱 vs agent 权限闸门的对照；Instruments vs agent trace。

---

### Phase 7: 收束——整件 mini-agent-harness (Week 7，T7 载体)
**核心目标**: 把 Phase 1–6 的组件收束为一个完整 harness：LLM(mock) + 工具注册 + 循环 + 上下文管理 + 权限 + eval，端到端实跑自证。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 7.1 | 组件整合 | 单一入口 CLI：任务输入 → harness 执行 → 结果与 trace | 架构整合 |
| 7.2 | 任务套件 | 3 个难度递进任务（单工具/多工具/需拒绝危险操作） | 任务设计 |
| 7.3 | 端到端 eval | 全任务通过率 + token 成本 + 失败分析 | eval 自证 |
| 7.4 | 架构复盘 | 「哪些组件值得、哪些是负债」的记账报告（对照 T7 概念题） | 架构取舍 |

- [ ] 能否不看文档手写该 Phase 核心代码？
