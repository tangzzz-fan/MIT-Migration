# T1 教练出题集：LLM 基座与核心心智

> 本线为新建 LLM 全栈线（MIT-LLM-Migration）。原料 = 学员 iOS/Swift 工程存量 + Python 线 T1–T6 成果（工程手感/线代/概率/async），教练按既有知识重建模型骨架；LLM 概念层对学员全空白。
> 学员人设：十年 iOS 老手、LLM 零基础（见 [[01-学员人设卡.md]]）；预期在「把 LLM 当确定性函数、混淆训练与推理、上下文当无限内存、幻觉当 bug」上暴露漏洞。
> 使用纪律：学员卡住按「弱→中→强」逐级给提示，禁止跳级；直接要答案 → 拒答并反问「你的 iOS 类比是什么、你先排除了什么」（C1/C2）。提示与评分要点在密卷（仅教练分支），本文件是题干版。

## 一、共识：5 个核心心智模型

| # | 模型 | 一句话骨架 | iOS 存量锚点 |
|---|------|-----------|------------|
| M1 | LLM = next-token 预测器 | 给定前缀，模型输出「下一个 token 的概率分布」，生成就是反复取分布、续写一个 token；iOS 键盘自动补全是它的玩具版 | 键盘联想词：只是词表、上下文与规模放大了一万倍 |
| M2 | 训练与推理是两件事 | 训练 = 海量数据上调整权重（离线、昂贵）；推理 = 权重冻结后只做前向计算（在线、按次计费）；对话时模型**不学习** | App 分发：训练是「开发编译期」，推理是「用户运行期」，运行时不改二进制 |
| M3 | 输出是采样，不是查表 | 同一输入可以有很多合法续写，解码策略（temperature/top-p）决定从分布里怎么选；随机性是内建的，确定性是特例 | 同一个 UITableView 数据源可以有不同的滚动轨迹——输出路径不唯一 |
| M4 | 上下文窗口 = 全部记忆 | 模型无状态：每次请求必须带全历史；「记得你」= 历史还在窗口里；窗口是硬预算，超了要截断，成本随长度涨 | HTTP 无状态请求：每次带全 cookie；窗口就是这一次请求的「内存上限」 |
| M5 | 幻觉是结构性产物 | 模型的目标永远是「产出最像人话的下一个 token」，没有内置「我不知道」开关；知识缺失时按分布编造，编得流畅 ≠ 编得对 | 自动补全从不拒绝补全——哪怕补出来的是错的，它也给最「像」的那个 |

学员自检要求：合上表复述 M1–M5 并各举一个自己使用 LLM 产品时见过的现象；读不懂 → 按零基规则先补前置。

## 二、争议：专家吵得最凶的 3 个焦点

**D1 「模型越大越聪明」还成立吗？scaling 的收益与工程的收益怎么分账？**
- 正方最强论据：scaling law 曲线显示损失随参数量/数据量/算力可预测地下降，多个「涌现能力」只在规模越过阈值后出现。
- 反方最强论据：单位成本的质量收益递减；大量真实任务用「小模型 + RAG + 工具 + 校验」就能解决，盲目上大模型是烧钱。
- 对迁移者的意义：工程师的正确姿势是「能力问题先试着转成工程问题」（检索、工具、eval），模型规模是最后的手段——这正是本线 T4–T6 的存在理由。

**D2 推理模型（长思维链）是不是该默认开？**
- 正方：数学/代码/多步规划类任务提升显著，「多想一会」直接换准确率。
- 反方：延迟与成本成倍上涨，简单任务上纯属浪费；思维链还带来新的不可控（过程不可尽审计）。
- 对迁移者的意义：立场要有边界——按任务难度与预算分层选型，而不是「一律最强」；这跟 iOS 里「不是所有场景都该上最重的架构」是同一个工程直觉。

**D3 幻觉能被「治好」吗？**
- 正方：检索接地（RAG）、引用约束、RLHF 教模型说「不知道」、输出校验，能把幻觉压到业务可接受。
- 反方：next-token 目标函数决定了「流畅优先」，模型没有真值的内部表示，幻觉只能压制不能根除。
- 对迁移者的意义：工程姿态不是「消灭幻觉」而是「为幻觉设计」——关键输出必校验、关键事实必检索、关键操作必人工确认（T3/T4/T6 的伏笔）。

## 三、概念拷问题（6 道，口述通道）

判定标准：能讲出「为什么」并迁移到新场景 = 过；只能复述名词 = 不过。**每题都必须有机制维度，只说现象不算回答。**

### C1 什么是 token？为什么 LLM 不是「按字处理」文本？

问题：用自己的话解释 token 是什么、它和「字符/单词」分别什么关系；然后解释：为什么同一句中文和同一句英文消耗的 token 数差异很大？为什么会出现「strawberry 里有几个 r」这类模型数错字母的现象？

### C2 你第二次问同一个问题，模型「内部」发生了什么？

问题：描述一次 LLM 调用的完整链路：输入如何变成输出。必须回答：① 训练和推理各发生在什么时候；② 为什么模型「不记得」你昨天的对话；③ 有人说「我跟模型聊久了它越来越懂我」，这句话哪里对、哪里错？

### C3 为什么同一个 prompt 每次输出不一样？temperature 和 top-p 各管什么？

问题：解释输出的随机性从哪一步产生（指出具体机制，不许只说「模型有随机性」）；temperature 和 top-p 分别如何改变这一步；然后给出你的工程判断：什么任务该把 temperature 调低、什么任务该调高，为什么？

### C4 上下文窗口是什么？「模型记得我」的真相是什么？

问题：解释上下文窗口的三个后果：① 为什么每次 API 调用要把全部历史带上；② 超窗会发生什么；③ 为什么长对话又贵又慢（不只是 token 计费这一个原因）。用一个 iOS 概念类比窗口，并说出类比的断裂处。

### C5 幻觉为什么不是 bug？工程师该怎么「为幻觉设计」？

问题：解释幻觉的机制成因（从 next-token 目标函数推，不许归因于「数据不好/模型偷懒」）；然后给出至少三条工程对策，每条说明它针对幻觉的哪个环节（生成前/生成时/生成后）。

### C6 「LLM 只是随机鹦鹉，什么也不真正理解」——给出你有边界的立场。

问题：这是争议题。先各给正反方一条最强论据，再给出你自己的立场，并说明：**什么条件下**你站哪边、你的判据是什么（可观察的行为判据，不许诉诸「意识/灵魂」）。

## 四、代码任务题（4 道，代码通道，挂 Phase 1 载体）

判定标准：本机 `.venv/bin/python` 跑通 + 输出符合预期 + 学员逐行能讲 = 过。代码落 `代码/T1/`，输出贴回作答稿。**全部用 mock（内置概率分布/规则响应），不调真实 API。**

```python

def encode(text: str, vocab: dict[str, int]) -> list[int]: ...
def decode(ids: list[int], vocab: dict[str, int]) -> str: ...
# 要求：encode→decode 往返无损（assert 验证）；打印中英同义句的 token 数对比
```

任务：给定一个固定概率分布（mock 模型的「下一步输出」），实现三种解码：greedy / temperature 采样 / top-p（nucleus）采样；各采样 1000 次统计输出分布，打印对比表，验证：① greedy 恒定；② temperature 越高分布越平；③ top-p 只在候选集内采样。

```python
# 脚手架
CANDIDATES = {"好": 0.45, "行": 0.25, "可以": 0.15, "也许": 0.10, "不好说": 0.05}
def greedy(dist: dict[str, float]) -> str: ...
def sample_temperature(dist: dict[str, float], T: float, rng) -> str: ...
def sample_top_p(dist: dict[str, float], p: float, rng) -> str: ...
# 要求：T=0.5/1.0/2.0 三档 + p=0.7/0.9 两档，各 1000 次的频率表
```
