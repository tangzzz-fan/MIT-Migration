## 一、概念题：提示梯与评分要点

### C1 agent 最小结构
- 弱提示：iOS 的主运行循环在干什么——等事件、分发、再等。如果「分发决策」交给模型呢？
- 中提示：三要素：模型决策（下一步做什么）、工具执行（对世界产生效果）、循环（结果喂回再决策）。脚本写死三次调用 = 路径固定，只是恰好调了 LLM。
- 强提示：模型决策改变的三件事：路径空间（同一任务可能走出不同调用序列）、失败模式（多了「决策错误」这类故障，如选错工具/死循环）、测试方式（不能只测固定路径，要测行为分布 → eval，T6 伏笔）。
- 评分要点：三要素齐 + 「写死步骤不是 agent」的论证 + 三个改变各一条 = 过；把 agent 定义成「自动执行任务」= 未过。
- 参考答案：agent 的身份在「决策者是谁」（M1/M5）。

### C2 function calling 与 schema
- 弱提示：Codable 为什么要有类型定义？模型发出的调用如果没有类型契约会怎样？
- 中提示：schema 三重作用：① 约束模型输出空间（只能发合法调用）；② 宿主可机器校验（参数类型/必填）；③ 描述字段是模型的「工具说明书」——选哪个工具靠它。
- 强提示：无 schema 的两类故障：解析侧（自由文本解析脆弱，格式漂移即崩）、行为侧（模型对工具能力理解靠猜，选错/传错参数概率上升）。描述字段 = 工具的使用文档进上下文，质量直接决定选型正确率——「可有可无」是错的。
- 评分要点：三重作用 + 两类故障 + 描述字段的作用 = 过；只说「结构化更好」= 半过。
- 参考答案：schema 是模型与宿主之间的编译期（M2），和 T3 结构化输出同构。

### C3 工具失败的三种策略
- 弱提示：网络请求失败你的 App 是直接崩吗？错误信息去了哪？
- 中提示：崩溃丢信息；静默重试是宿主越权决策（可能重复不该重复的操作）；回填让「有上下文的决策者」处理——模型能看到错误详情并换策略。
- 强提示：回填是 agent 姿势的原因：错误也是观察（M3），模型有全量上下文做判断（换参数/换工具/放弃）。边界：鉴权失败、配额耗尽、重复同一错误 → 熔断退出或上报人工，不该让模型无限试（呼应 M4 停滞检测与 T6 权限）。
- 评分要点：三策略对比 + 「错误即观察」论证 + 熔断边界 = 过。
- 参考答案：错误恢复是循环设计的一部分，不是异常处理的附属品。

### C4 终止条件
- 弱提示：网络重试你只设「最多 N 次」吗？超时呢？预算呢？
- 中提示：三种机制：成功信号（模型输出最终答案标记）、硬上限（轮数/token）、停滞检测（动作哈希重复计数）；各防：模型不说完成、模型乱试、模型兜圈子。
- 强提示：空转场景：查不到结果就用同样参数反复查——停滞检测记最近 k 次调用的（工具+参数）指纹，重复即干预（换提示/退出）。token 预算进终止条件：长循环上下文膨胀，成本与注意力稀释（T2 C6 回收）都在涨，预算是钱的护栏。
- 评分要点：三机制 + 停滞检测具体设计 + token 预算 = 过；只说最大轮数 = 半过。
- 参考答案：终止条件是 agent 的「内存管理与超时纪律」（M4），工程直觉直接平移。

### C5 workflow vs agent
- 弱提示：你什么时候用硬编码路由、什么时候用动态分发？
- 中提示：判据：路径可预见性（步骤固定 → workflow）、错误代价（高危流程要可审计 → workflow）、输入开放性（任务形态多变 → agent）。
- 强提示：退回例：发票报销流程（步骤固定、需审计）——agent 的灵活性是负债。上进例：开放式研究任务/多仓库代码修改（路径无法预先枚举）——workflow 写不全。多数现实系统在中间：workflow 骨架 + 局部 agent 节点。
- 评分要点：≥2 判据 + 双向例子 = 过；「agent 更先进所以用 agent」= 未过。
- 参考答案：M5 的落地 = 决策权归属是设计选择，不是技术进步。

### C6 状态住在哪里
- 弱提示：T1 M4——上下文有什么硬限制？第 2 轮的信息到第 9 轮还在窗口里吗？
- 中提示：三个住所：上下文（默认，但受窗口与截断支配）、外部存储（T4 记忆/文件系统，需主动读写）、工具自身状态（如有状态服务）——各自的限制：上下文会被压缩截断、外部存储要模型「记得去读」、工具状态对模型不可见需查询。
- 强提示：全靠上下文的风险：长任务触发截断（T1 Q3 遗忘实验回收），早期关键信息（约束/凭证/中间结论）被挤出 → agent 行为漂移。工程对策：关键状态显式落外部 + 每轮摘要（T6 上下文管理伏笔）。
- 评分要点：三住所 + 各自限制 + 长任务风险与对策 = 过。
- 参考答案：agent 的记忆工程 = T4 记忆分层在循环里的实例。

## 二、争议焦点参考立场

- **D1 多 agent**：合理立场「先问单 agent + 好工具是否够；多 agent 的判据是上下文隔离与分工收益 > 通信成本」；为拆而拆 = 半过（设计模式线反滥用纪律回收）。
- **D2 ReAct vs Plan**：合理立场「按任务可预见性选：开放任务 ReAct、结构化任务 Plan，且计划要允许按观测修订」；站死流派 = 半过。
- **D3 自由度**：合理立场「自由度是设计出来的：白名单 + 校验 + 审批分层给出」；「放开才智能」= 未过（T6 前哨）。

## 三、代码题：评分要点与提示

### Q1 function calling 协议
- 评分要点：schema 结构完整（name/description/parameters）；解析→校验→执行链路打印完整；非法参数用例被校验拦截并有错误观察返回；能讲「模型只提议、宿主才执行」。
- 参考要点：校验返回的错误要格式化得像「给模型看的观察」，为 Q3 回填铺垫。

### Q2 ReAct 循环
- 评分要点：思考/行动/观察三段式 trace 打印；终止双条件（最终答案 + 最大轮数）都实装；断言轮数符合预期；能指出循环里「决策点」在哪一行。
- 参考要点：mock 的决策规则用「关键词 + 已见观察」驱动即可，重点是循环骨架不是 mock 智能。

### Q3 错误恢复
- 评分要点：FlakyTool 故障注入生效；A 崩溃点与 B 恢复轨迹对比打印；注释回答「哪些错误该熔断」有具体类别（鉴权/配额/重复错误）。
- 参考要点：B 的恢复要体现「模型看到错误详情后改参数」——错误观察的内容质量是题眼。

### Q4 workflow vs agent 对拍
- 评分要点：两版同任务跑通且轨迹打印；三维度记账（灵活性/失败模式/可测试性）各有具体内容；选型结论与记账一致（结论与账不符 = 半过，设计模式线记账纪律回收）。

## 四、使用纪律

- 判分只认证据：概念看「决策权归属」这条主线是否贯穿，代码看循环 trace 与恢复轨迹；「会用框架但讲不清谁在决策」= 半过。
- 失真自查：学员全题全对 → 人设失效；把 agent 说成「自动化脚本的高级形式」还判过 = 心智失守。
