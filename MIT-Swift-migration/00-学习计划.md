# MIT 三问攻坚：OC 老手迁移现代 iOS 栈 —— 学习计划

> 目标：学员 agent（人设见 [[01-学员人设卡.md|01-学员人设卡]]）用 MIT 三问法快速掌握 Swift、SwiftUI、Concurrency、Combine 及对应性能优化，达到能独立完成 UIKit/OC 项目向现代栈迁移的水平。
> 方法基座：[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]（MIT 三问学习法四点改造 + C1–C5 纪律，已自包含，不依赖外部知识库）。
> 分支：学员分支 `feat/mit-swift-study-student`（教练分支 `feat/mit-swift-study` 含密卷与旧轮产出）。本文件只是计划与台账；出题/作答/批改产出另起文件。

## 一、原料策略

教材原为外部知识库的 iOS 笔记集（见第二节「原料出处」列）；本仓库脱库自包含后，**原料不再是运行时依赖**——五轮出题集的模型骨架与考点已由教练按既有知识重建并自洽（各 `T{n}-01` 文件头有注明），出题/判定只读本目录文件即可完成。OC 对照资产作为学员的「存量骨架」保留：他已有 UIKit/GCD/RunLoop/内存管理功底，三问的共识模型主动挂靠这些旧知做迁移锚点（如 GCD → async、delegate → 状态注入、手动 retain/release → ARC + 值语义）。

## 三、每主题执行流程（教练 + 学员双 agent 仿真）

沿用双 agent 仿真格式（四件套规范见 [[04-方法论基座-MIT三问与测试协议.md|方法论基座]]，格式范例即本目录 T1–T5 既有产出），每主题产出四件套：

1. **教练出题**：读上表对应原料 → 出「共识五模型 + 争议三焦点」→ 出拷问题（概念口述题 + 代码任务题）。弱/中/强提示与评分要点在 `T{n}-01-教练密卷-<主题>.md`（仅教练分支，学员禁阅）；题干落 `T{n}-01-教练出题-<主题>.md`。
2. **学员作答**：严格按 [[01-学员人设卡.md|人设卡]] 作答——该对的凭 OC 功底对，该错的地方如实错，禁止全知全能。落 `T{n}-02-学员作答-<主题>.md`。
3. **批改判定**：逐题判 过关 / 半过（拆判分点）/ 未过；概念题看「能否讲出为什么并迁移新场景」，代码题看本机是否跑通。落 `T{n}-03-批改与判定-<主题>.md`。
4. **费曼写回**：全过的主题用自己的话重写一篇草稿落本目录（`T{n}-04-费曼草稿-<主题>.md`）；未过的缺口记台账复攻，不写草稿。

**代码通道环境**：代码题的最小可跑实现放本目录 `代码/` 子夹（每个 `.swift` 文件顶部注释标注对应题号），用本机 `swift` CLI 运行，输出贴回批改文件作为硬验证证据。「AI 说我懂了」不算数，跑通才算数。完整工程骨架不孤立写片段，挂靠 [[02-项目驱动实践路线.md|项目驱动实践路线]] 的对应 Phase 迭代项目（绑定关系见第七节）；Instruments 类交付物在仿真阶段记为「待真机验证」，不冒充硬验证。

## 四、执行纪律（照搬测试协议 C1–C5）

| # | 纪律 | 在本攻坚中的含义 |
|---|------|----------------|
| C1 | 先弱提示 | 学员卡住时先只定位概念不给方向；学员立刻想到答案说明提示太强，降级重出 |
| C2 | 拒答代学 | 学员直接要答案 → 拒给，反问已排除了什么 |
| C3 | 双通道强制 | 概念口述过关后必须追加代码任务，只有口述不算过关 |
| C4 | 台账如实 | 未过不得写「过关」，半过必须拆判分点注明缺口 |
| C5 | 产出落本目录 | 全部产出落迁移目录内，不直写外部知识库 |

失败标准（出现即说明仿真失真，需重跑）：学员 agent 全题全对（人设失效）、或代码题全靠教练代写也能判过（C3 失守）。

## 六、执行节奏

- 每主题一轮闭环（出题 → 作答 → 批改 → 费曼），跑完记台账再开下一主题；未过缺口先复攻再前进。
- 拷问与项目双线并行：拷问题暴露的缺口优先复攻，项目迭代提供硬验证实体；两边互相出题（项目里踩的坑可转为拷问题）。
- 进度：学员版——每闭卷一轮（作答 + 代码实跑 + 自批）后，在第五节台账填一行；全部闭环后在此收束。

## 七、代码通道载体绑定（对接 [[02-项目驱动实践路线.md|项目驱动实践路线]]）

| 主题 | 绑定 Phase | 主力载体迭代（代码题优先挂靠） |

| T4 Combine 互通 | Phase 4 | 4.2 防抖重试缓存管道（操作符）、4.3 @Published 数据流、4.4 Combine vs async 边界判定 |
| T5 性能优化整合 | Phase 5 | 5.1 长列表 60fps 优化、5.4 Actor vs 锁基准测试、5.5 综合项目迁移收益报告 |

规则：

1. 拷问的代码题若主题命中上表，优先直接长在该迭代项目上，避免孤立片段；未命中才退回最小 `.swift` 片段。
2. 项目交付物（如 Instruments 报告、编译时间分析）在仿真阶段无法真机执行时，按 C4 如实记「半过/待真机验证」，不记过关。
3. 原路线的「关键对比任务」（OC 与 Swift 双实现）作为每主题费曼草稿的固定骨架：费曼稿必须含一段迁移对比小节。
