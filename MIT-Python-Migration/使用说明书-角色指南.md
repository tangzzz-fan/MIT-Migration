# 使用说明书：学员与教练角色指南

> 本文档说明本学习线的两个角色（学员 / 教练）各自能做什么、怎么做、不能做什么。协议细则见 [[00-学习计划.md|学习计划]] 第三节，学员侧红线见 [[学员须知.md|学员须知]]（仅学员分支）。

## 〇、一分钟看懂本仓库的玩法

一条学习线 = 一轮轮「拷问闭环」：**教练出题 → 学员闭卷作答+代码实跑 → 教练阅卷判定 → 学员复攻销账 → 费曼写回**。为防止「先看答案再复述」的假学习，内容拆放在两个 git 分支上：

| 分支 | 归属角色 | 有什么 | 没什么 |
|------|---------|--------|--------|
| `feat/mit-python-study`（教练分支） | 教练 | 计划/台账、题干、**密卷**（评分要点+三级提示+参考答案）、批改 | 学员作答过程 |
| `feat/mit-python-study-student`（学员分支） | 学员 | 骨架文档、题干、作答、代码、费曼稿 | **密卷和批改**（作答期间物理不可见） |

合并方向铁律：**只有「学员 → 教练」允许 merge**（那是交卷→阅卷）；教练→学员永远只允许单文件选择性同步。`main` 是 Swift 线归档，Python 线不碰。

## 一、学员角色（真人学习者，或扮演学员的 agent）

### 每轮标准动作

1. **领题**：`git checkout feat/mit-python-study-student`。新题 = 教练在本分支新提交的 `T{n}-01-教练出题-<主题>.md`（只有题干：五模型骨架、争议焦点、拷问题目，无提示无答案）。
2. **闭卷作答**：写 `T{n}-02-学员作答-<主题>.md`——每题先写思考过程再给结论，附自评三档（有把握/半懂半猜/纯猜）。概念与代码分开答。
3. **代码硬验证**：实现放 `代码/T{n}/`，一律 `.venv/bin/python` 实跑（依赖：`uv pip install --python .venv/bin/python <包>`），文件头写撞墙记录，输出贴回作答稿。**没跑起来 = 没验证**。
4. **交卷**：`git add -A && git commit -m "feat(T{n}): ..."`——提交即交卷。
5. **等判定**：教练合并阅卷后口头/对话传达判定。`T{n}-03` 批改文件闭轮前只留教练分支（防止复攻时看到提示），**闭轮后**可请教练同步到本分支归档复盘。
6. **复攻**：半过/未过的题逐级向教练要提示（弱→中→强），把要到的提示如实记在作答稿里补答，直到销账。**绝不直接要答案**。
7. **费曼**：全部销账后写 `T{n}-04-费曼草稿-<主题>.md`（脱稿重推五模型 + Swift/iOS 对照 + 60 秒讲稿；T2/T3 还须含「给 iOS 同事讲懂」自检段落），commit 交教练复核。

### 学员纪律红线（违反 = 该轮作废重跑）

- 不许 `git checkout feat/mit-python-study` 去看密卷/批改；
- 不许 `git merge`/`cherry-pick` 教练分支任何内容进学员分支；
- 自评必须诚实：「纯猜」不许写「半懂」；数学题只算出结果没直觉的如实标半懂；
- 不许拿教练的代码或答案充数（C3：代码通道必须自己跑通）。

### 环境备忘

- 虚拟环境：`MIT-Python-Migration/.venv`（CPython 3.12.13，uv 创建；numpy/torch 已装）。
- 重建：`uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python numpy torch`。

## 二、教练角色（出题与判定 agent，由用户指令驱动）

### 每轮标准动作

1. **出题**（教练分支）：写两份——
   - `T{n}-01-教练出题-<主题>.md`（题干：共识五模型 + 争议三焦点 + 概念六题 + 代码四题，代码题挂靠项目路线 Phase）；
   - `T{n}-01-教练密卷-<主题>.md`（逐题判分点 + 弱/中/强三级提示 + 复习线变式题 + 人设预期漏洞 + 失真自查清单）。**密卷永不进学员分支。**
2. **同步题干**：切学员分支，`git checkout feat/mit-python-study -- "MIT-Python-Migration/T{n}-01-教练出题-<主题>.md"` 单文件同步，单独提交；随后 `git ls-tree -r --name-only HEAD | grep 密卷` 自查为 0。
3. **阅卷**：学员交卷后，在教练分支 `git merge feat/mit-python-study-student`，按密卷判分点出 `T{n}-03-批改与判定`：首轮判定表（过关/半过/未过）+ 复攻记录（提示级别与销账）+ 失真自查。复习线执行：会算无直觉=半过、答得太顺追加变式题。
4. **记账**：更新 `00-学习计划.md` 掌握度台账（两行：概念/代码）与进度行，提交。
5. **复攻主持**：学员要提示时按密卷提示梯逐级给（先弱后强），不许越级、不许直接给答案。
6. **复核费曼**：学员提交费曼稿后 merge 复核，整轮收官。
7. **闭轮归档（可选）**：将 `T{n}-03` 选择性同步到学员分支供复盘。

### 教练纪律

- 判定只认证据：概念看推理链、代码看实跑输出；撞墙记录须有真实报错，编造的墙当场作废；
- 每次同步后必做泄漏自查；学员分支出现提示/答案内容 = 该轮作废重跑；
- 失真自查：首轮漏洞分布须与人设卡预期对应，全题全对 = 人设失效需重跑。

## 三、一轮的完整 git 时序（参考）

```
[教练分支] 出题：题干+密卷                → commit
[学员分支] 选择性同步题干（单文件）        → commit（自查无密卷）
[学员分支] 作答 T{n}-02 + 代码实跑        → commit（交卷）
[教练分支] merge 学员分支（阅卷）          → commit
[教练分支] T{n}-03 批改 + 台账更新         → commit
[学员分支] 复攻补答（如有）+ T{n}-04 费曼  → commit
[教练分支] merge 学员分支（复核收官）       → commit
```

六主题进度以 `00-学习计划.md` 第五节台账为准。
