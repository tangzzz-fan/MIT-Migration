# 学员须知（本文件只存在于学员分支）

> 你当前在学员分支 `feat/mit-python-study-student`。教练分支 `feat/mit-python-study` 上放着评分要点、三级提示与参考答案（`T{n}-01-教练密卷`），**本分支刻意不含这些内容**——这是防假学习的机制，不是遗漏。

## 你在这里能做什么

1. **看题干**：教练同步过来的 `T{n}-01-教练出题-<主题>.md`（共识模型 + 争议焦点 + 拷问题干，无提示无答案）。
2. **闭卷作答**：在本目录写 `T{n}-02-学员作答-<主题>.md`——每题先写思考过程再给结论，附自评三档（有把握 / 半懂半猜 / 纯猜）。
3. **代码硬验证**：代码题实现放 `代码/T{n}/`（文件头注释标对应题号），一律用项目虚拟环境 `.venv/bin/python` 跑通（依赖安装走 `uv pip install --python .venv/bin/python <包名>`），运行输出贴回作答稿。
4. **费曼写回**：主题判定后写 `T{n}-04-费曼草稿-<主题>.md`（含 Swift/iOS 对照小节）。
5. **提交即交卷**：作答完成就 `git commit`，教练会合并本分支回教练分支阅卷。

## 纪律红线（违反 = 该轮作废重跑）

- **不许切到教练分支看密卷**，不许 cherry-pick/merge 教练分支的任何内容到本分支；
- 卡住时按 C1/C2 逐级向教练要提示（弱→中→强），把要到的提示如实记在作答稿里，**绝不直接要答案**；
- 自评必须诚实：「纯猜」不许写成「半懂」；数学题只算出结果没直觉解释的，如实标半懂；
- 代码没跑起来 = 没验证，不许凭「应该能跑」交卷。

## 流程速记

```
教练出题（教练分支）→ 题干选择性同步到本分支 → 你闭卷作答 + 跑代码 + 提交
→ 教练合并本分支回教练分支阅卷（学员→教练是唯一合法 merge 方向）
→ 你按判定复攻或写费曼稿
```

注意：git log 里出现的 merge 都是「学员分支并入教练分支」——那是教练拿你的交卷去阅卷，不是合进 `main`；`main` 始终停在 Swift 线归档，与你的日常作答无关。

## 操作手册（git 日常循环）

```bash
# 1. 开工：日常只在学员分支干活
git checkout feat/mit-python-study-student

# 2. 领题：新题 = 教练在本分支新提交的 T{n}-01-教练出题 文件（选择性同步放入，不含密卷）
git log --oneline -3

# 3. 作答：写 T{n}-02，代码放 代码/T{n}/，实跑
.venv/bin/python 代码/T2/Q1-xxx.py

# 4. 交卷：提交即交卷
git add -A && git commit -m "feat(T{n}): ..."

# 5. 判定与费曼：教练口头/对话传达判定；全销账后写 T{n}-04 再 commit
```

批改文件 `T{n}-03` 闭轮前只留教练分支（防止复攻时看到提示）；**闭轮后**教练可把它选择性同步到本分支归档复盘。

方法全文见 [[04-方法论基座-MIT三问与测试协议.md|方法论基座]]，学习计划与台账见 [[00-学习计划.md|00-学习计划]]（台账由教练在教练分支维护）。
